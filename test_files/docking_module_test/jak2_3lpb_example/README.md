# JAK2 3LPB Redocking Example

This example shows how ANTIOCH-VS can fetch the public JAK2 crystal structure
`3LPB`, prepare both receptor chains around the co-crystallized ligand `NVB`,
and redock `NVB` with both DOCK6 and AutoDock Vina.

The example is intentionally portable. Paths in the YAML files are relative to
this directory, and executable locations are placeholders that should be edited
for your machine or cluster.

## What Is Included

- `dock6_inputs/chainA` and `dock6_inputs/chainB`: receptor PDBs and `NVB`
  MOL2 ligand/reference files generated by `fetch_prepare_receptor.py`.
- `dock6_chimera/chainA` and `dock6_chimera/chainB`: Chimera-produced receptor
  MOL2 and DMS surface files for DOCK6.
- `vina_inputs/chainA` and `vina_inputs/chainB`: receptor and ligand PDBQT files
  generated for Vina.
- `configs/`: portable example configs for Chimera, DOCK6, and Vina.
- `output_poses/`: successful docked ligand pose files from the smoke-test runs.
- `results_summary.csv`: top score observed in the included pose outputs.

## Receptor And Ligand Preparation

The receptor prep script can fetch `3LPB` directly from RCSB, keep one protein
chain as the receptor, and extract the matching `NVB` ligand from the same
chain. In `3LPB`, `NVB` is residue `1133` in both chains A and B.

From the repository root:

```bash
export PREP="$PWD/docking_module/receptor_prep/fetch_prepare_receptor.py"

cd test_files/docking_module_test/jak2_3lpb_example

python "$PREP" \
  --pdb-id 3LPB \
  --receptor-chains A \
  --ligand-resname NVB \
  --ligand-chain A \
  --ligand-resseq 1133 \
  --output-dir dock6_inputs/chainA \
  --prefix 3LPB_chainA \
  --docking-software dock6 \
  --write-prepared-complex \
  --keep-all-files

python "$PREP" \
  --pdb-id 3LPB \
  --receptor-chains B \
  --ligand-resname NVB \
  --ligand-chain B \
  --ligand-resseq 1133 \
  --output-dir dock6_inputs/chainB \
  --prefix 3LPB_chainB \
  --docking-software dock6 \
  --write-prepared-complex \
  --keep-all-files
```

The reference ligand centers reported by the prep step were:

- Chain A: `114.454 65.922 10.449`
- Chain B: `77.328 111.100 21.507`

## DOCK6 Workflow

DOCK6 needs Chimera-prepared receptor charges and DMS molecular surfaces before
the DOCK6 grid and flexible docking stages. Edit the Chimera configs if your
Chimera executable or container setup differs:

```bash
export CHIMERA_PIPE="$PWD/../../../docking_module/dock6_pipeline/chimera_pipeline.py"
python "$CHIMERA_PIPE" --config configs/chimera/3LPB_chainA_chimera.yaml
python "$CHIMERA_PIPE" --config configs/chimera/3LPB_chainB_chimera.yaml
```

Then edit `configs/dock6/3LPB_chainA_dock6.yaml` and
`configs/dock6/3LPB_chainB_dock6.yaml` so `dock6_dir` and `dock6_executable`
point to your DOCK6 installation. The example uses:

- `sphere_radius: 10.0`
- `box_margin: 8.0`
- `max_orientations: 5000`
- `num_final_scored_poses: 10`

The DOCK6 config quotes values such as `"yes"` so YAML does not convert them
to Python booleans before they are written into DOCK6 input files.

Run DOCK6:

```bash
export DOCK6_PIPE="$PWD/../../../docking_module/dock6_pipeline/dock6_pipeline.py"
python "$DOCK6_PIPE" --config configs/dock6/3LPB_chainA_dock6.yaml
python "$DOCK6_PIPE" --config configs/dock6/3LPB_chainB_dock6.yaml
```

Included successful outputs:

- `output_poses/dock6/chainA/3LPB_chainA_receptor_prepared_wH_wcH_flex_scored.mol2`
- `output_poses/dock6/chainB/3LPB_chainB_receptor_prepared_wH_wcH_flex_scored.mol2`

The smoke-test top DOCK6 grid scores were `-74.286766` for chain A and
`-75.215126` for chain B.

## Vina Workflow

For Vina, the same `fetch_prepare_receptor.py` script writes receptor and ligand
PDBQT files. This example uses the crystal heavy-atom receptor as the Meeko
input and passes `--meeko-allow-bad-res`, because the deposited `3LPB` chains
contain incomplete crystal residues outside the `NVB` pocket.

```bash
python "$PREP" \
  --pdb-id 3LPB \
  --receptor-chains A \
  --ligand-resname NVB \
  --ligand-chain A \
  --ligand-resseq 1133 \
  --output-dir vina_inputs/chainA \
  --prefix 3LPB_chainA \
  --docking-software vina \
  --vina-receptor-source crystal \
  --meeko-allow-bad-res \
  --write-prepared-complex \
  --keep-all-files

python "$PREP" \
  --pdb-id 3LPB \
  --receptor-chains B \
  --ligand-resname NVB \
  --ligand-chain B \
  --ligand-resseq 1133 \
  --output-dir vina_inputs/chainB \
  --prefix 3LPB_chainB \
  --docking-software vina \
  --vina-receptor-source crystal \
  --meeko-allow-bad-res \
  --write-prepared-complex \
  --keep-all-files
```

Run Vina CPU after editing `vina_exe` if your executable is not simply `vina`:

```bash
export VINA_CPU="$PWD/../../../docking_module/vina_pipeline/vina_cpu_pipeline.py"
python "$VINA_CPU" --config configs/vina/3LPB_chainA_vina_cpu.yaml
python "$VINA_CPU" --config configs/vina/3LPB_chainB_vina_cpu.yaml
```

Included successful outputs:

- `output_poses/vina/chainA/3LPB_chainA_NVB_ligand_out.pdbqt`
- `output_poses/vina/chainB/3LPB_chainB_NVB_ligand_out.pdbqt`

The smoke-test top Vina affinities were `-10.01 kcal/mol` for chain A and
`-9.882 kcal/mol` for chain B.

## Notes

- `--add-missing-residues` is not required for this example. ANTIOCH-VS skips
  terminal missing residues by default even when internal missing-residue
  modeling is requested.
- `--meeko-allow-bad-res` lets Meeko remove incomplete crystal residues during
  Vina receptor conversion. Inspect the reported residues before production
  docking if your target pocket differs from the `NVB` binding site.
- The included pose outputs are demonstration artifacts, not benchmark-quality
  validation data. Production redocking should include pose RMSD checks against
  the crystallographic ligand.
